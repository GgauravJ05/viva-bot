Process notes: from PDF to a searchable index

What happens when you click Process notes. No AI is called here: everything runs on your laptop. This index is what the quiz, viva and doubt features search later.

Step by step: where each step lives in the code

StepWhat happensFile : line
0The student uploads PDFs and clicks Process notes. The app first checks the limits (max 5 files, 150 pages).app.py:193 → 125 · 127 · 136
1–2extract_pages reads each page's text with pypdf, keeps its page number, and flags empty (scanned) pages.app.py:132 → rag.py:39
3–4chunk_pages cuts each page into ~800-character chunks with 100 characters of overlap. Chunks never cross a page, so each has one page number to cite.app.py:143 → rag.py:74
5A new in-memory NotesIndex is created and the chunks are added.app.py:142–143 → rag.py:131
6–7embedder.encode turns every chunk into a vector: 384 numbers that capture its meaning. Model all-MiniLM-L6-v2, running on the laptop.rag.py:135
8–9collection.add stores each vector in Chroma with its text, file name and page number.rag.py:136
10–11The index is kept in the session, and the sidebar shows files · pages · chunks.app.py:145 · 167

Nothing is written to disk. Close the app and the index is gone.
